# Brand

The @xtandard/audit mark is the xtandard "X" with a shield on its upper-right arm. The X is built
like its siblings': a big `>` chevron, a lower-right stroke and a short upper-right arm. Webhooks
puts a hook on that arm and flags puts a flag; audit puts a shield with a check cut out of it,
meaning "verified, tamper-evident". The mark comes as an app icon, a bare symbol and a wordmark
lockup. Everything lives in [`docs/assets/`](assets/). The SVGs are the masters, and every PNG and
ICO is built from them.

The masters are clean geometry: rounded polygons, one heater-shield outline with the check as an
even-odd hole, and linear gradients. They use no filters except the soft shadow in the app icon, and
embed no fonts or images. They are generated by `scripts/brand/` (below), so a change to the mark,
a colour, the tagline or a lockup's layout is a code change, not a hand edit of the SVGs.

## Files

**Everything people see as a logo is an SVG.** Rasters exist only where a format requires one and
nobody sees them as an icon on a page: `social.png` (`og:image` must be a raster), and `favicon.ico` /
`apple-touch-icon.png` as `<head>` fallbacks. There are no PNG logo or lockup variants.

The ICO and the touch icon are `<head>` fallbacks only           |

Regenerate the masters, then rebuild the three rasters from them:

```sh
bun run brand:masters  # uv run scripts/brand/build.py: writes every SVG in docs/assets/
bun run brand:assets   # sh scripts/brand-assets.sh: rsvg-convert (librsvg) + magick (ImageMagick 7), oxipng when installed
bun run brand:check    # rasters present, src/ui/brand copies equal to docs/assets
```

`brand-assets.sh` also copies `favicon.svg`, `symbol.svg` and `symbol-light.svg` into `src/ui/brand/`, which the admin
SPA bundles (served from its own origin, so no cross-origin fetch at runtime).

### The generator

`scripts/brand/build.py` is a [uv](https://docs.astral.sh/uv/) script: its inline metadata
declares fontTools and uharfbuzz, so `uv run` needs no venv or install step. On its first run it
downloads the variable `Urbanist[wght].ttf` and `JetBrainsMono[wght].ttf` from google/fonts into
`scripts/brand/fonts/`, which is gitignored: the fonts are never committed. Its output is
deterministic, so rerunning it on an unchanged checkout leaves `git status` clean.

| File         | What it holds                                                                                                                                                       |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mark.py`    | The symbol's geometry: the X grid (height, slope, stroke width, gaps, the arm's top) and the shield (size, offset, how far its point sinks into the arm, the check) |
| `build.py`   | The palette, the app icon (surface, rim, orbits, brackets, shadow), the favicon, the lockups, the monochrome files and the social card (tagline and command text)   |
| `text.py`    | Instances a variable font at a weight, shapes text with HarfBuzz and returns its outline as SVG path data                                                           |
| `geom.py`    | Rounded polygons (arcs at each corner), line intersections and the check's outline                                                                                  |
| `palette.py` | Prints the OKLCH and contrast values of the palette table below (`python3 scripts/brand/palette.py`, no dependencies)                                               |

### Where each file goes

- **README header** (the README ships to npm, which does not ship `docs/`): a `<picture>` that picks
  the dark or light horizontal lockup with `prefers-color-scheme`, by absolute
  `raw.githubusercontent.com` URL so it renders on npm as well as GitHub:

  ```html
  <p align="center">
    <picture>
      <source
        media="(prefers-color-scheme: dark)"
        srcset="
          https://raw.githubusercontent.com/xantiagoma/xtandard-audit/main/docs/assets/lockup-horizontal-dark.svg
        "
      />
      <img
        alt="xtandard-audit"
        src="https://raw.githubusercontent.com/xantiagoma/xtandard-audit/main/docs/assets/lockup-horizontal-light.svg"
        width="420"
      />
    </picture>
  </p>
  ```

  npm ignores `<source>` and shows the light lockup on its white page, which is the right one.

- **Docs site** (Starlight): `logo: { dark: lockup-horizontal-dark.svg, light: lockup-horizontal-light.svg, replacesTitle: true }`
  (or `symbol.svg` beside the text title), `favicon: favicon.svg`, plus `head` entries for
  `favicon.ico` (with `sizes="16x16 32x32 48x48"`), `apple-touch-icon.png` and
  `og:image` = `social.png` by absolute URL.
- **Admin UI / portal / React embeds**: `src/ui/brand/favicon.svg` as the tab icon, and the bare
  symbol in the header — `symbol-light.svg` in the light theme, `symbol.svg` in the dark one. No tile
  behind it.
- **Favicon order** in any HTML head: `favicon.ico` (with `sizes`) first, then `favicon.svg`
  (`type="image/svg+xml"`, which modern browsers prefer), then `apple-touch-icon.png`.
- **Social preview**: `social.png`.

## Why a shield

The brief offered two emblems for "tamper-evident audit log": a shield with a check, or two
interlocked chain links (the hash chain). The shield wins at 16–32 px, where favicons and tab icons
live:

- Its silhouette (flat top, pointed bottom) is one solid shape that survives as a few pixels; the
  check is a single bold hole that still shows as a dark mark at 16 px and as a tick at 32 px.
- Two interlocked links need two holes and an over/under crossing inside the same area the shield
  uses. At 32 px each hole is about 2 px and the crossing disappears, so the links read as a blob.
- A chain-link glyph is the near-universal "hyperlink" icon, so even when legible it says "URL",
  not "audit". A shield with a check says "verified, protected", which is what the hash chain and
  checkpoints give the reader.

The shield stands on the arm the way webhooks' hook ring hangs off its neck and flags' flag flies
from its pole: the arm stays, and the emblem is its end.

## Wordmark

`xtandard-audit` in **Urbanist** Black (900), tracking −1.2%, kerned by HarfBuzz, converted to
paths: the SVGs need no font. `xtandard-` is `xa-paper` on dark and `xa-ink` on light; `audit` is
always the lime gradient. This is the same face, weight and tracking as xtandard-image's wordmark.
The social card adds Urbanist SemiBold (600) for the tagline and **JetBrains Mono** Regular for the
command.

(artwork made with the font), not the font software, so the OFL's conditions on distributing the

The fonts are credited in `NOTICE` at the repository root. `scripts/brand/text.py` makes the outlines: it
instances the variable `Urbanist[wght].ttf` (and `JetBrainsMono[wght].ttf`) at the weight above with
fontTools' `instancer`, shapes the text with HarfBuzz (`kern` on) and draws each glyph with
fontTools' `SVGPathPen`.

## Geometry

The X is drawn on a grid where it is 260 units high and every diagonal runs 0.9 units across per
unit down (a little steeper than 45°, like the siblings). Every stroke is 92 units wide measured
horizontally, and the lower stroke and the arm sit 26 units (horizontally) off the chevron's outer
edges. The arm's top is flat, 44 units below the X's top. The shield is 114 × 124 units, its point
centred on the arm's top and sunk 8 units into it; the check is a 24-unit stroke cut out of it.
With the shield the symbol is 326 × 332 units (`symbol.svg`), and the shield rises 72 units (28%
of the X) above the X's top.

- **App icon**: the symbol is 530 units high (scaled 1.596) and centred, 4 units low; the brackets
  are 196 high, 92 deep, 30 thick with round caps and joins, centred on the X's middle, their points
  130 units from the edges. The orbit circle (r 350) and arcs (r 422) are the family's; the arcs
  are turned (−80° to −30° and 150° to 100°) so their end dots clear the brackets. Corner radius
  224 of 1024 (21.9%).
- **Favicon**: the symbol 840 units high on the flat `xa-ink` square, same corner radius.
- **Horizontal lockup**: 96 units high = the symbol's height; the wordmark's baseline is the X's
  bottom, its x-height half the X's height, starting 22% of the height after the symbol.
- **Stacked lockup**: 205 units high; `audit`'s baseline is the X's bottom, `xtandard-` 1.6
  x-heights above it, x-height 27% of the height.

**Clear space**: keep the shield's width (35% of the symbol's height) free on every side of the
symbol or lockup. The app icon needs no clear space inside its square; outside it, keep 10% of its
width.

**Minimum sizes**: app icon 48 px (use the favicon set below that, down to 16 px), symbol 20 px
high, horizontal lockup 24 px high (about 160 px wide), stacked lockup 48 px high. Below these use
the favicon alone.

## Do and don't

Do:

- Use the dark lockup on dark backgrounds and the light lockup on light ones; on GitHub, switch with
  `<picture>` and `prefers-color-scheme`.
- Use the app icon wherever a square avatar is expected, and the favicon set below 48 px.
- Use the monochrome lockups on photos, coloured backgrounds or in one-colour print.
- Reference the files by absolute URL outside the repository (npm, other sites).

Don't:

- Recolour the symbol (no blue: that is xtandard-image's colour), swap gradient directions or flatten
  the gradients into one lime, except in the monochrome files.
- Put the dark-surface lime symbol or `audit` on white: it is under 2:1. Use the light lockup.
- Set the wordmark in another font, or as live text in a different weight.
- Put the dark lockup (near-white `xtandard-`) on a light background, or the light one on dark.
- Stretch, rotate, outline or add effects (glow, bevel, extra shadows) to the symbol.
- Rearrange the symbol: the chevron stays on the left, the shield on the upper-right arm, upright.
- Swap the shield for another emblem (the hook and the flag belong to webhooks and flags), or fill
  the check in.
